## 2024-05-25 - [Inefficient Alert Sorting]
**Learning:** Found an inefficiency in `backend/app.py` `get_alerts()` where alerts from `Reading` and `EventLog` tables are merged and sorted in memory using a string concatenation of `data` and `hora` keys (`f"{x["data"]} {x["hora"]}"`), and filtering is done in a Python loop over the `Reading` result set.
**Action:** The memory hints explicitly state: "When merging and sorting multiple database result sets (like `Reading` and `EventLog`) for API responses, utilize raw datetime objects (e.g., via a temporary `_ts` key in result dictionaries) instead of string concatenation as sort keys to improve performance and ensure chronological accuracy." and "To optimize API endpoints fetching sensor or event data (e.g., `/api/alerts`), prioritize database-level filtering (e.g., using `.filter(Model.column != value)`) over Python-side loop filtering and use list comprehensions for efficient data transformation into dictionaries." We will optimize `/api/alerts` to filter at the DB level and sort by datetime objects.
